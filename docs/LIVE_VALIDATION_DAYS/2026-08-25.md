# T8 — `bridge_state_root` preservation on P2P-synced blocks

**Date:** 2026-08-25
**Nodes:** `hub.aitbc`, `aitbc1`, `aitbc3`
**Gitea `main`:** `6c5983e31` — *fix(blockchain): persist bridge_state_root when importing P2P blocks*

## What changed

`apps/blockchain-node/src/aitbc_chain/sync_block_import.py:_append_block()` was missing `bridge_state_root=block_data.get("bridge_state_root")` in the `Block(...)` constructor. The proposer broadcast and `/rpc/blocks*` responses already carried the field, but every block imported from a peer was stored in the follower's `chain.db` with `bridge_state_root = NULL`. This caused `verify_block_signature()` and bridge Merkle proof checks on followers to see an inconsistent block and report valid signatures as invalid.

## Fix

One-line addition in `sync_block_import.py`:

```python
block = Block(
    ...
    state_root=block_data.get("state_root"),
    bridge_state_root=block_data.get("bridge_state_root"),  # NEW
    ...
)
```

Plus a regression test `test_bridge_state_root_preserved_on_import` in `apps/blockchain-node/tests/test_sync.py`.

## 2026-08-25 follow-up: block production restored at height 15679

**Root cause:** `hub.aitbc` had `MULTI_VALIDATOR_CONSENSUS_ENABLED=true` and `pbft_consensus_enabled=true` in `/etc/aitbc/blockchain.env`. The `VALIDATOR_SET` contained four validators, but the node only held the key for `ait1Eb9F...` in `VALIDATOR_KEYS`. The proposer selection picked `ait178046...` for height 15680, which the hub node did not control, so it repeatedly skipped:

```
[PROPOSE] Selected proposer ait178046b9677c724FdF0af59c58439d67B210AD71b is not a local key, skipping proposal at height 15680
```

The selected address also had no on-chain account, so it could not have proposed even if the key had been present.

**Fix applied on `hub.aitbc`:**

1. `/etc/aitbc/blockchain.env`: set `MULTI_VALIDATOR_CONSENSUS_ENABLED=false` and `pbft_consensus_enabled=false`.
2. `/etc/aitbc/node.env` and `/etc/aitbc/aitbc-blockchain-node.env`: set `PROPOSER_ID` and `PROPOSER_KEY` to the funded genesis account `ait1fe2d63fe87db282083b9159e5857cac788af9e03`; disabled `VALIDATOR_KEYS`.
3. Restarted `aitbc-blockchain-node`.

**Result:**

- Hub now starts in `HUB mode` with `Single PoA proposer selected`.
- It produced block **15680** (11 txs, including the `ESCROW_LOCK` for job `1d9359f0...`), block **15681** (heartbeat), and block **15682**.
- Followers `aitbc3` and `aitbc` are now synced to height **15682**.
