### 2026-08-26 PBFT block sync fix for `aitbc`, `aitbc1`, `aitbc3`, `hub2`

PBFT-era blocks store a `pbft_certificate` (commit messages) in `block_metadata` instead of the older `attestations` list. `ProposerSignatureValidator._validate_attestations()` only looked for `attestations`, so every PBFT block was rejected.

    - `message_type == "commit"`
    - `block_hash` matches the block
    - `digest == sha256(block_hash:sequence_number:view_number)`

    - signature verifies with `verify_consensus_message()`

## Daily-life friction and CLI improvement suggestions

### Wallet/address UX
1. **Unify 0x and ait1/aitbc1 wallet display.** `wallet balance` for 0x-backed wallets returns 0 even when the on-chain account has funds; `account get` is canonical. The CLI should normalize all addresses to the chain's canonical form before querying balance.
2. **Wallet selection.** Customer commands (`market run`, `ai submit`) auto-pick wallets. Add `--wallet` to `market run` and `market transcribe`/`process` so the customer controls funding.
3. **Wallet service vs local wallet files.** `ai submit` only loads from `~/.aitbc/wallets`; `market offer` uses wallet service. A single `aitbc wallet use <name>` default or `--wallet-name/--wallet-path` everywhere would remove the guesswork.

### Marketplace/job UX
4. **Link `market list` to `market run`.** `market list` prints `Plugin ID` (e.g. `ollama-llama3.2-3b`), but `market run` needs the on-chain `offer_id` (`sw_offer_...`). Either `market list` should expose `offer_id` or `market run` should accept the `Plugin ID` and resolve it internally.
5. **`market list --output json` missing.** Many CLI commands do not honor the global `--output` option, so they cannot be scripted.
6. **Escrow safety in `market run`.** When escrow creation fails, `market run` prints a warning and still runs inference, leaving the provider unpaid. This should be a hard error or require `--no-escrow-confirm`.
7. **One-command cancel+refund.** `ai cancel` leaves payment as `escrowed`; the user must then run `ai refund` or `market escrow refund`. `ai cancel` should offer `--refund` or auto-refund a cancelled/pending job.

### Agent/discovery UX
8. **Agent commands need defaults.** `agent status` and `agent inbox` should default to the only (or configured) agent when no `--agent-id` is given.
9. **Agent coordinator availability.** Agent discovery/inbox fail when the agent-coordinator is not running. The CLI should either start a local fallback or print a clear "agent-coordinator is not running" guide.

### Dashboard/observability
10. **Dashboard wallet balances.** Both `dashboard customer` and `dashboard shop` show `Balance: N/A`. They should query the blockchain RPC or wallet service and display real balances.
11. **Dashboard payment status sync.** Customer dashboard still showed `payment_status: escrowed` after on-chain refund. It should reflect the live coordinator/blockchain state.
12. **Job tracking for `market run`.** Direct `market run` jobs are invisible in `aitbc ai jobs` because they bypass the coordinator. A `--track` option or a `market jobs` command would let customers see and accept/refund these jobs.

### New feature ideas for daily island life
13. **`aitbc ipfs pin <cid>` for customers.** After buying an `ipfs` storage offer, there is no CLI to hand a CID to the provider and pay. A `aitbc ipfs host --cid ... --days N` command that locks escrow, pins, and later unpin would complete the IPFS shop flow.
14. **`aitbc node doctor` / `aitbc system check`.** A single command that checks wallet, IPFS, GPU, miner, coordinator and prints a readiness report would help shop operators every morning.
15. **`aitbc market run` for whisper/ffmpeg.** Currently only `ollama` is supported in `market run`. Adding `transcribe` and `process` as first-class `market run` aliases or subcommands would make the marketplace useful for all offer types from one entry point.
16. **One-command customer end-to-end.** `aitbc market run <offer> "prompt"` is close, but adding `--accept` and `--timeout` and routing through the coordinator so `ai accept` works would close the acceptance-gate loop.
17. **Offer management for the shop.** `aitbc market offer` works, but there is no `aitbc market offer list` or `aitbc market offer disable` to manage a shop's published offers.

## Immediate quick-win recommendation

The smoothest daily path is `aitbc market run`, but right now it is unsafe (unpaid provider) and hard to discover (Plugin ID vs offer_id mismatch). Fixing the CLI so `market list` shows `offer_id` and `market run` aborts on escrow failure would make the AI marketplace usable for real customers and shop earnings.

- The coordinator's `acquire_next_job` used every `ONLINE` miner (including stale `devin-miner` and `e2e-test-miner`) as a candidate for the higher-reputation check, so inactive high-reputation miners blocked dispatch to the live shop miner.
- `execute_job` only handled `inference`, `transcribe`, and `reencode`, but `ai submit --type=ollama` produced `type: "ollama"`, causing the first assigned job to fail with `Unsupported job type: ollama`.

**Fixes committed and pushed**
- `apps/miner/production_miner.py`: coordinator heartbeat now reports `status: "ONLINE"`; `execute_job` maps `ollama`/`llama` -> `inference`, `whisper` -> `transcribe`, `ffmpeg` -> `reencode`.
- `apps/coordinator-api/.../services/jobs.py`: `acquire_next_job` filters the `online_miners` comparison pool by recent heartbeat (`COORDINATOR_MINER_HEARTBEAT_CUTOFF_SECONDS`, default 300s).
- `apps/coordinator-api/.../services/miners.py`: `online_count()` applies the same heartbeat cutoff.
- Docs: updated `docs/releases/v0.24.0/change.log`.

**Live validation after fixes**
