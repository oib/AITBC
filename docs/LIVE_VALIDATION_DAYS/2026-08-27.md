# Escrow persistence test fix and deploy (2026-08-27)

**Gitea `main`:** `a721f2b81` — *fix(escrow): use is_(None) for NULL checks in load_from_db query*

## What was analyzed and fixed

`apps/blockchain-node/tests/contracts/test_escrow_persistence.py::TestEscrowManagerPersistence::test_load_from_db_loads_only_active_escrows` was failing because `EscrowManager.load_from_db()` used `select().where(EscrowRecord.released_at is None, EscrowRecord.refunded_at is None)`. In SQLAlchemy/SQLModel this does not generate `IS NULL`; it evaluates the `InstrumentedAttribute` with Python `is`, producing a literal boolean and returning no rows.

Fix:
- Changed the query to `EscrowRecord.released_at.is_(None)` and `EscrowRecord.refunded_at.is_(None)`.

Validation:
- The single failing test now passes.

# Signature fix and paid E2E validation (2026-08-27)

**Gitea `main`:** `8bc7f648c` — *fix(blockchain-node): canonicalise unsigned tx fields and ignore gossip tx_hash*

## What was validated

The follower `aitbc` was rejecting block 609 with `Invalid signature for transaction ...` on an `ESCROW_LOCK` for job `354a98bb...`. The root cause was that block gossip attaches a computed `tx_hash` field to the transaction dict, while the node verifier included that field when reconstructing the signed message. The client had signed the transaction before `tx_hash` existed, so the recovered message differed from the one that was signed.

Code changes:
- Added a shared `_unsigned_tx_fields()` helper in `apps/blockchain-node/src/aitbc_chain/rpc/utils.py`.
- Both `verify_transaction_signature()` and `sign_transaction_data()` now use it.
- `escrow_routes._compute_tx_signing_hash()` also uses it for `ESCROW_RELEASE` consistency.
- Excluded fields: `signature`, `sig`, gossip-attached `tx_hash`, and the internal `value` alias when `amount` is present.
- Added regression tests in `apps/blockchain-node/tests/test_v0516_regression.py` covering `tx_hash` and `value` aliasing.

Deployment and validation:
- Committed and pushed to Gitea `main` from `aitbc3`.

- Restarted `aitbc-blockchain-node` and `aitbc-blockchain-rpc` on all four nodes.

- All four nodes advanced to height 622 with the same last block hash.
