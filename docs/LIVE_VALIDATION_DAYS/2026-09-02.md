## PBFT mesh fault-tolerance, state-root corruption, and recovery (continuation of same day)

- Rolled out multi-peer `MeshGossipBackend` with `GOSSIP_MESH_PEER_URLS`, fan-out publish, and deduplication across all four validators.
- Fault-tolerance test: stopped `hub.aitbc` for ~4 minutes.
  - `aitbc3`, `hub2.aitbc`, and `node1` produced one block (2846) while hub was down, then stalled.
  - After hub restart, all four nodes converged to height 2846, but the computed account state root (`0xe00873c3...`) diverged from the block header (`0xa7a8f15d...`).
- Diagnosis:
  - A failed PBFT proposal on the hub applied two GPU marketplace transactions, then called `session.rollback()`.
  - New `Transaction` objects and account state changes made inside `begin_nested()` savepoints were not fully rolled back, producing orphan `block_height=2847` transactions and a corrupt account state.
  - Followers then synced the corrupt state.
- Recovery:
  - Reconstructed a consistent database from `node1`'s `chain.db.bak-20260902-node1-ahead` (head 2795) by replaying blocks 2796–2846.
  - Replay produced the canonical block 2846 state root `0xa7a8f15d...` and the correct `0xd3d...` account state.
  - Preserved each live database as `chain.db.corrupt.20260902-1145`.
  - Replaced `chain.db` on all four validators and restarted hub-first.
- Rollback bug fix (`poa.py`):
  - Removed per-transaction `begin_nested()` savepoints and the `session.add()` of new `Transaction` records inside them.
  - New/updated `Transaction` records are now collected and `session.add()`-ed only after all state transitions for the block succeed.
  - Governance and duplicate checks are now done before `apply_transaction` so a skipped tx cannot leave account mutations.
  - On exception, the session is rolled back and the block aborted.
  - Committed/pushed as `3acefcda7` on gitea `main`; pulled and restarted on all four nodes.
- Validation after fix:
  - All four nodes converge at height **2860** with matching head hash and state root.
  - Re-ran hub-down test: no state-root corruption, no orphan transactions, hub catches up cleanly.
  - The network still stalls after one block while `hub.aitbc` is offline; PBFT view-change does not rotate to an available proposer. This is the remaining liveness issue.
  - **Superseded later the same day** by the round-takeover work below, and closed on 2026-09-03 by `d3861a2eb`; see `LIVE_VALIDATION_DAYS/2026-09-03.md`.
