# Script environment variables

The operational scripts under `scripts/` and `dev/testing/` used to carry the
authors' own fleet in them: host names, ssh aliases from one workstation's
`~/.ssh/config`, a public domain, and marketplace and shop URLs pointing at one
deployment. That made the scripts fail on anyone else's machine and published
the fleet in a public repository. Those identifiers are now environment
variables with no fleet-specific defaults.

This page is the reference for them. Nothing here is a node runtime setting —
for `/etc/aitbc/*.env` see [configuration.md](./configuration.md) and
[ENVIRONMENT_CONFIGURATION.md](../blockchain/ENVIRONMENT_CONFIGURATION.md).

## Fleet addressing

| variable | required? | used by |
|---|---|---|
| `AITBC_NODE0_HOST` | required where used | ssh/RPC target for node0 |
| `AITBC_NODE1_HOST` | required where used | ssh/RPC target for node1 |
| `AITBC_NODE2_HOST` | optional | node2, in `scripts/monitoring/fleet-config-check.sh` |
| `AITBC_NODE3_HOST` | required where used | node3, in the p2p and blockchain-communication tests |
| `AITBC_HUB_HOST` | optional | hub, in `fleet-config-check.sh` |
| `AITBC_HUB1_HOST` | optional | second hub, in `fleet-config-check.sh` |

A value is whatever `ssh` and `curl` can reach — an ssh_config alias, a
hostname, or an address. Scripts that cannot do anything useful without one use
`${AITBC_NODEn_HOST:?...}` and fail immediately with the variable name; the
monitoring check uses `:-` instead and reports `UNREACHABLE`, because a
half-configured fleet report is more useful than no report.

There is deliberately no default for any of these. A default would be one
deployment's host, which is wrong everywhere else — that is the bug this whole
set of variables exists to fix.

## Service endpoints

| variable | required? | meaning |
|---|---|---|
| `AITBC_SHOP_URL` | required | base URL of the shop node. Read by 62 workflow scripts and the four scenario tests. The scenario tests first source `/etc/aitbc/.env.scenario` if it exists and only fall back to this variable, so on a configured node nothing needs to be exported. |
| `AITBC_MARKETPLACE_URL` | required | default for `aitbc market ratings --remote-url`. Without it the flag must be given; there is no default, because the old one silently pushed every deployment's ratings to one island's marketplace. |
| `AITBC_FLEET_DOMAIN` | required | the domain the fleet publishes under, e.g. `example.net`. `fleet-config-check.sh` builds `hub.$AITBC_FLEET_DOMAIN` and friends from it. |

## Deployment targets

| variable | default | meaning |
|---|---|---|
| `AITBC_CONTAINER` | `aitbc` | Incus container name that `deploy-to-aitbc-container.sh` deploys into. |
| `AITBC_DNAT_TARGET` | unset | address the Incus host DNATs published ports to. When unset, `deploy-blockchain-and-explorer.sh` publishes nothing from the host and says so — it does not guess. |
| `AITBC_NODE1_CONTAINER_SSH` | required | ssh target for the blockchain container on node1. Was a private `~/.ssh/config` alias, so the scripts using it only ran on one workstation. |
| `AITBC_GIT_REMOTE` | `origin` (update.sh), else required | Gitea remote name or clone URL for `setup.sh` / `update.sh`. Also settable with `--gitea` or `--remote`. |

`scripts/deployment/deploy/deploy-env.sh` is the shared file where the
deployment-target variables are set for `scripts/deployment/deploy/*.sh`.

## Capability checks

| variable | default | meaning |
|---|---|---|
| `AITBC_GENESIS_KEYSTORE` | `/var/lib/aitbc/keystore/genesis.json` | path the genesis-authority scripts test for. |

Three workflow scripts must run on the genesis authority node. They used to
decide that by comparing `hostname` against one deployment's node name, which
answers the question only on that deployment. They now test for the keystore,
which is what actually makes a host the genesis authority. Set this if the
keystore lives elsewhere.

## Firewall / nginx

| variable | default | meaning |
|---|---|---|
| `AITBC_FLEET_CIDR` | `127.0.0.1/32` | CIDR allowed in the nginx snippet generated by `scripts/workflow/23_scaling_preparation.sh`. The default allows only the loopback: a wrong-but-open default here would expose the endpoint on every deployment that did not notice the variable. |
