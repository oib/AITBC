# Scenario 37: ZK Proof for High-Value Jobs

## Goal

Submit a high-value AI job that requires and receives a ZK receipt proof.
The proof is generated by the coordinator and verified before escrow release.

## Preconditions

- Coordinator service has `COORDINATOR_ENABLE_ZK_VERIFICATION=true`.
- `COORDINATOR_ZK_HIGH_VALUE_THRESHOLD` is set (e.g. `10`).
- `COORDINATOR_ZK_REQUIRE=true` is optional; otherwise only jobs with
  `--zk-proof-required` request a proof.
- Customer and provider wallet addresses are set.

## Steps

1. Submit a job with payment above the high-value threshold and request a ZK
   receipt proof:
   ```bash
   export CUSTOMER_WALLET_ADDRESS=<customer>
   export SHOP_WALLET_ADDRESS=<shop>
   aitbc ai submit --payment 15 --type inference --prompt "test" \
     --zk-proof-required
   ```

2. Wait for the job to complete. The CLI can poll:
   ```bash
   aitbc ai status --job-id <job-id>
   ```

3. Expected result:
   - `state`: `COMPLETED`
   - `payment_status`: `released`
   - `zk_status`: `verified`
   - `zk_proof_id`: a non-null proof identifier

## Notes

- Jobs with `payment` below the threshold complete without a ZK proof unless
  `--zk-proof-required` is set.
- The coordinator stores `zk_proof_id` in the job receipt and uses it during
  settlement if `use_zk_proof` is enabled.
- `zk_status` values are typically `null`, `pending`, `verified`, or `rejected`.
- If `COORDINATOR_ENABLE_ZK_VERIFICATION=false`, the coordinator answers that
  ZK verification is not enabled and `zk_status` remains `null`.
